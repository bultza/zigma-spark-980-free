# Pairing DHCP handover

The native Ciccio firmware can leave its pairing DHCP server running after joining the home Wi-Fi network. The local network manager correctly refuses a foreign DHCP owner, but the previous handover stopped only the native cloud processes, WPA supplicant and DHCP client. Activation could therefore lose connectivity with `ownership_conflict`.

Mode backend V1.3 validates and stops the native pairing server before starting local networking. It requires one udhcpd process, the expected executable, native command line, a regular configuration file and exactly one wlan0 interface declaration. Ambiguous processes or configurations fail closed. The existing identity-checked TERM/wait/KILL path handles servers that ignore TERM, and the handover verifies no udhcpd remains.

Validation: 120 installer tests pass. In the private Ciccio QEMU lab, clean pairing through installation and accepted activation passed without rebooting; a subsequent boot retained local mode, SSH, web and control readiness. This covers the emulated Ciccio userspace with the lab kernel/device adapters, not physical hardware or every firmware variant. Existing RC17/RC18 distribution archives were not regenerated by this change.
